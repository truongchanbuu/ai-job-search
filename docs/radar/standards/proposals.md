# Standard — Upwork proposal drafting

**Editable writing personality:** private `proposal-style.md`. **Marketplace actions:** manual owner submission outside Radar; no write adapter.

## Default approach

1. Read exact client problem, desired result, constraints and screening questions.
2. Select one or two verified, closely relevant project examples.
3. Open with a job-specific observation or achievable outcome (not a generic self-introduction).
4. Explain the first practical steps and what information is needed from client.
5. Close with one relevant question or low-friction next step.

## Constraints

- Prefer concise, natural English; specific beats impressive-sounding.
- Never claim a training/demo project was paid commercial client work.
- No invented years, clients, technologies, metrics or certifications.
- No promise of fixed price/delivery date without user approval.
- Answer screening questions separately. Show uncertainty / required clarifications.
- A draft is not a submitted proposal; the user reviews every marketplace action.
- Preserve source job ID, profile evidence references, revision and draft history.

## Quality gate

A reviewer checks `specificity`, `truthfulness`, `feasibility`, `clarity`, `tone`, `screening answers`, and `no platform violations`. Failures produce suggestions, not fabricated replacements.


Phase 5 uses a local reviewed draft workflow, without calling Upwork write tools.
Generated candidate claims are verbatim shareable verified facts with their
actual experience context. Provider plan prose is validated separately. Editing
and final approval create new immutable revisions; a generated/regenerated draft
never becomes a submitted application. See [Phase 5](../plan/phase5-ai.md).


## Minimal drafting briefs

The [researched template catalog](../plan/proposal-templates.md) adds optional,
owner-selected briefs. Put the client's problem first, explain a practical first
step, cite one relevant verified/shareable fact with its actual context, and use
one closing question or next step. Shortening must preserve requested details.
Template ceilings are editorial choices, not a conversion guarantee. Generic
fillers, unresolved slots, irrelevant evidence and extra questions fail the new
brief's output checks. Screening answers remain separate; human review remains
required. The existing non-template path remains available.
